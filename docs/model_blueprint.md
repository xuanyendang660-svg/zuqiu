# 全球足球唯一精准比分模型方案

## 1. 模型定位

这套模型只做一件事：每场比赛输出一个精准比分。它不输出比分包，不用多个备选兜底，也不把 `1-0`、`1-1`、`2-1` 当作默认安全区。

新版不再让模型只靠全网格泊松排序。默认使用 `scorebook` 比分思维池：

```text
主胜盘面：10 20 21 30 31 32 40 41 42 50 51 52
平局盘面：00 11 22 33
客胜盘面：01 02 12 03 13 23 04 14 24 05 15 25
```

这 28 个比分是每场必须逐项过一遍的盘口比分板。模型不会只挑低风险比分，也不会跳过 `4-0/0-4/4-1/1-4/5-0/0-5/5-1/1-5/4-2/2-4/3-3`。此外，`scorebook` 还保留 `胜其他/平其他/负其他` 代表比分，例如 `4-3/3-4/4-4/5-3/3-5/6-0/0-6/6-1/1-6/6-2/2-6/7-0/0-7`。

模型会把它们分成五类：

- `draw_ladder`：`00/11/22/33/44`
- `narrow_result`：`21/12/32/23`
- `one_side_break`：`31/13/41/14/51/15`
- `clean_sheet_break`：`10/01/20/02/30/03/40/04/50/05`
- `exchange_war`：`42/24/52/25`

同时仍保留 `full` 模式。如果要完整扫描网格，可以切换：

```powershell
python -m score_model.cli examples\matches_12_sample.json --pretty --score-profile full
```

如果后续你想继续放大，可以在 CLI 里调整：

```powershell
python -m score_model.cli examples\matches_12_sample.json --pretty --max-total-goals 14 --max-team-goals 12
```

默认 `scorebook` 覆盖 `5-2`、`2-5`、`5-1`、`1-5`、`4-4`、`5-0`、`0-5` 等核心极端形态。`full` 模式则可以继续扩到更大的比分网格。

## 2. 双引擎结构

第一套是 `真实比赛引擎`。它回答：如果完全不看市场，这场比赛真实进球结构应该是什么样。核心输入包括联赛节奏、球队攻防、近期 xG、伤停、轮换、战意、天气、裁判和主客场差异。

第二套是 `市场拆解引擎`。它回答：市场在防什么比分，又可能漏掉什么比分。核心输入包括 `1X2`、市场预期主客进球、精准比分赔率和市场可信度。

市场拆解引擎不能把盘口当成赛果原因。机构不是决定比赛结果，而是把比赛结果的不确定性变成资金分布和盈利工具。模型会先用真实比赛引擎形成 `football_favorite`，再用市场拆解引擎形成 `market_favorite`；两者冲突且市场热度/诱导风险高时，进入 `market independence`，降低盘口方向和市场预期进球权重。

如果精准比分赔率不完整，缺失比分不会再被误判成巨大错价，而是回落到市场预期进球分布。这个修正很关键，否则大比分会因为“没有报价”被错误抬高。

## 3. 情景分流唯一比分选择

模型默认使用 `adaptive` 模式。它不是顺盘口，也不是全反盘口，而是先把比赛分成 `正路真热`、`假热冷门`、`平局黏住`、`对攻乱战` 四类情景，再让对应比分进入竞争。

四个模式：

- `adaptive`：默认模式，结合数据、盘口热度、xG、动机和波动先做情景分型。
- `balanced`：保守，容易靠近市场和真实概率中心。
- `aggressive`：打破舒服比分，但仍较尊重盘口方向。
- `contrarian`：反市场，会淡化盘口同向和大众比分。

流程如下：

1. 生成完整比分网格。
2. 计算每个比分的真实概率。
3. 反推市场隐含概率。
4. 每个总球层选一个层内冠军。
5. 在层冠军之外，再允许非常规比分挑战最终答案。
6. 如果当前答案太接近盘口大众方向，会强制反大众比分重新竞争。

最终值核心公式：

```text
final_value =
  real_probability
  * market_factor
  * structure_score
  * cold_bonus
  * scenario_multiplier
  * (1 - conflict_penalty)
  * (1 - comfort_penalty)
  * (1 - tail_penalty)
```

`comfort_penalty` 会压低拥挤舒适比分，比如 `1-1`、`1-0`、`2-1`。  
`tail_penalty` 不是限制极端比分，而是要求极端比分必须有结构支撑，避免纯粹乱飞。  
`cold_bonus` 会抬高有概率底线、有结构解释、有市场错价的非常规比分。
`public_penalty` 会压低盘口热门方向和高热精准比分，例如市场强压主胜时，`2-0 / 2-1 / 3-1` 不会天然胜出，`2-2 / 1-2 / 3-2` 会被拿来重新比较。

## 4. 不舒服比分怎么胜出

以下比分不会被系统排除：

- 大比分：`3-2`、`4-2`、`4-3`、`5-2`
- 单边穿盘：`3-0`、`4-0`、`5-0`、`0-3`、`0-4`、`1-4`
- 极端尾部：`4-1`、`1-4`、`5-1`、`1-5`、`6-1`、`5-3`、`7-2`
- 高比分平局：`2-2`、`3-3`、`4-4`
- 小球冷门：`0-1`、`1-0`、`0-2`、`2-0`

它们要胜出，需要满足至少一部分条件：

- 联赛波动率高。
- 双方防守压力大。
- 伤停集中在后防。
- 市场总进球预期偏高。
- 精准比分赔率相对真实概率有错价。
- 战意或赛程导致比赛开放。

`shape arbitration` 会把这些比分拆成独立形态判断。极端零封、单边带丢球、互爆、高平和小球冷门不能互相套同一套逻辑；每种形态必须有自己的 xG、盘口、资金热度、积分战意或末轮剧本支撑。

`result script arbitration` 是形态判断之前的一层。它先把比赛拆成九类：小球正路、大球正路、大球互爆正路、大球打穿正路、小球平局、大球平局、小球冷门、大球互爆冷门、大球打穿冷门。盘口热门只影响 `normal/fake_hot/upset` 信号，不直接决定最终方向；只有当 xG、总进球线、资金热度、战意、末轮风险和双方进球能力共同支持时，对应剧本才允许挑战当前最高分。

## 5. 全球联赛分层

全球联赛不能共用一个平面模型。生产版本应采用四层结构：

- `全球基础层`：学习足球比赛通用进球规律。
- `联赛画像层`：学习每个联赛的节奏、平局率、大比分尾部和主客场差异。
- `球队强度层`：学习每支队的攻防强度、风格、稳定性和主客差异。
- `比赛修正层`：处理临场伤停、首发、轮换、赛程、天气、裁判和战意。

小联赛、低数据联赛和新升班马使用贝叶斯收缩。数据少时先继承联赛基线，样本变多后再释放球队个性。

## 6. 回测指标

精准比分天然低命中，所以不能只看唯一命中率。生产回测至少看五层：

- `唯一比分命中率`
- `总球层命中率`
- `方向层命中率`
- `市场超额值`
- `分布校准度`

现在分布校准要看 `T=0..10`，并检查模型是否真的给过 `4+`、`5+`、`6+` 的比分，而不是表面开放、实际仍然缩回舒服比分。
