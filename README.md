# 足球市场—机制—比分模型 v0.1

这不是一个“看到热门就反、看到模板就躲”的比分生成器。它把赛前判断拆成可冻结、可复现、可回测的四层：

1. **基本比分先验**：主客队预期进球与基础强弱。
2. **比赛状态混合**：低事件、常规、控场、互爆、主队单边打穿、客队单边打穿。
3. **市场校准**：用 KL 投影校准 1X2、2.5 大小和 BTTS，而不是把盘口直接当答案。
4. **逐球许可与停止机制**：主客队第1球、第2球、第3球以上分别授权；大众比分簇只用于审计，绝不自动降权。

## 为什么重建

旧的叙事式流程有四个系统性错误：

- 把大众簇里的另一个比分误称为“反大众”；
- 因为反馈“太顺/太模板”在没有新证据时修改方向；
- 把“必须追分”错误转换成“必然进球”；
- 用单峰比分分布压低 4-1、5-1、6-1 等连续崩盘尾部。

本项目用代码强制以下纪律：

- 预测冻结后，只有官方首发、核心伤停、盘口跨档、规则或场地等硬证据才能解锁修改；
- 市场大众簇不会被机械惩罚；
- 每支球队 0/1/2/3+ 球分层处理；
- 大球区分互爆与单边崩盘；
- 回测保存实际比分在完整矩阵中的排名，而不只统计是否精确命中。

## 数据与开源基础

建议组合使用：

- **penaltyblog**：Dixon–Coles、双变量泊松、贝叶斯模型、赔率去水、亚洲盘与大小球概率；
- **StatsBomb Open Data**：事件、阵容及部分 360 数据，用于构造 xG、推进、压迫和比赛状态特征；
- 真实赔率时间序列、官方阵容与伤停需要单独接入合规数据源。

注意：开源数据通常不能覆盖所有当日小联赛和实时盘口。数据缺失必须降置信度，不能用猜测补齐。

## 运行示例

```bash
football-model examples/match.yaml
```

输出包括：

- 唯一冻结比分；
- 1X2、Over 2.5、BTTS 校准概率；
- 前12个比分；
- 舒适比分簇审计警告。

审计警告不会自动改答案。它只要求分析者说明：为什么这个大众落点比零封、尾部和平/冷分支更强。

## 模型结构

### 状态混合

`ScenarioWeights` 包含：

- `low_event`
- `normal`
- `home_control`
- `away_control`
- `shootout`
- `home_blowout`
- `away_blowout`

这些状态分别生成比分矩阵，再混合成先验，避免把所有比赛压成一个普通泊松峰。

### 市场校准

`calibrate_distribution` 对先验做最小信息损失的指数倾斜，使结果尽量匹配：

- 主胜/平/客胜；
- Over 2.5；
- BTTS。

市场约束只校准总体结构。它不会替代阵容、战术和逐球许可。

### 逐球许可

`GoalLicenses` 分别控制：

- 主客队第1球；
- 主客队第2球；
- 主客队第3球以上；
- 平局、主队领先、客队领先的停止机制。

例如“客队可能进一个”不会再自动把 3-0 改成 3-1；“主队有优势”也不会自动把 0-0 改成 1-0。

## 回测指标

必须连续冻结测试，不允许赛后改写：

- 精确比分；
- 实际比分在矩阵中的排名；
- 负对数似然；
- 1X2方向；
- 总球分区；
- BTTS/零封；
- 极端右尾召回率；
- 相对收盘市场的增量表现。

## 当前边界

v0.1 是一个可测试的底座，不是已经被证明有效的盈利系统。下一步必须接入真实历史数据与赔率快照，完成不少于30场的赛前冻结测试，再决定哪些状态权重和逐球许可需要调整。
